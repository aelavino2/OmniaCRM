# Конфигурация Claude Code

Общекомандные настройки Claude Code для OmniaCRM. Всё здесь **коммитится** и действует у всех, кто работает с репозиторием, — кроме `settings.local.json`, который личный и закрыт `.gitignore`.

| Путь | Что здесь лежит |
|---|---|
| `settings.json` | Разрешения на инструменты, переменные окружения, хуки |
| `settings.local.json` | Личные настройки поверх общих. Не коммитится, создаётся автоматически |
| `commands/` | Слэш-команды проекта |
| `agents/` | Субагенты проекта |
| `skills/` | Навыки проекта |
| `hooks/` | Скрипты для хуков из `settings.json` |

> **Не клади сюда документацию в виде `.md`-файлов.** Claude Code считает слэш-командой каждый `.md` в `commands/` и субагентом — каждый `.md` в `agents/`. Файл `README.md` в этих папках станет командой `/README`. Всё пояснительное — только в этом файле.

`commands/` пуста намеренно: команду стоит заводить под реальную повторяющуюся задачу, а не заранее. В `skills/` и `agents/` лежит набор, перенесённый из ECC под стек проекта (Kotlin/Java, Spring Boot, PostgreSQL, Gradle) — происхождение и лицензия описаны в `skills/THIRD-PARTY.md`.

## commands/ — слэш-команды

Один файл — одна команда: `review-api.md` → `/review-api`. Тело файла становится промптом. Фронтматтер необязателен:

```markdown
---
description: Краткое описание для списка команд
argument-hint: <ветка>
allowed-tools: Bash(git diff:*), Read
---

Текст промпта. Аргументы подставляются как $1, $2 или $ARGUMENTS.
```

Заводить команду стоит, когда одна и та же просьба повторяется третий раз.

## agents/ — субагенты

Один файл — один агент: `db-reviewer.md` → агент `db-reviewer`. Работает в отдельном контексте и возвращает только результат.

```markdown
---
name: db-reviewer
description: Когда вызывать этого агента
tools: Read, Grep, Glob
model: sonnet
---

Системный промпт агента.
```

Полезны для задач с большим объёмом чтения и коротким выводом: обзор миграций, аудит API-контракта, поиск по кодовой базе.

## skills/ — навыки

Один каталог — один навык: `skills/migrations/SKILL.md`. В отличие от команд, навык Claude подключает сам, когда описание совпадает с задачей.

```markdown
---
name: migrations
description: Когда применять — по этому тексту навык и выбирается. Пиши конкретно.
---

Инструкции: шаги, конвенции проекта, примеры.
```

Рядом с `SKILL.md` можно класть шаблоны, скрипты, справочники.

Кандидаты для OmniaCRM, когда дойдёт до кода: конвенции миграций Flyway, шаблон нового REST-эндпоинта, чеклист обработки вебхука.

## hooks/ — скрипты хуков

Исполняемые скрипты, на которые ссылается `hooks` в `settings.json`. Хук запускает сам Claude Code в ответ на событие (перед вызовом инструмента, после правки файла, в конце ответа) — не модель.

Типичное применение появится вместе со сборкой: автоформатирование после записи в `*.kt`/`*.java`, запрет правок в защищённых путях. Пути в `settings.json` пиши через `$CLAUDE_PROJECT_DIR`, чтобы хук работал независимо от текущего каталога.
