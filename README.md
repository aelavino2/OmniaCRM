## Зачем этот проект

Я пишу разные сайты — рекламник для барбершопа, магазин очков, лендинг для дизайнера мебели — и каждый раз заново изобретаю одно и то же: регистрацию пользователей, приём заявок, хранение заказов, уведомления клиенту. Вместо того чтобы клепать это по кругу, я строю **одно CRM-ядро**, к которому все мои будущие сайты и Telegram-боты будут подключаться как клиенты через API.

Это не попытка обогнать amoCRM или Bitrix24 — рынок готовых CRM большой и зрелый (см. [«Чем это не является»](#чем-это-не-является)). Это личный инфраструктурный проект и практика: спроектировать мультитенантный бэкенд, продумать API-контракт для сторонних интеграций и довести его до продакшна на собственных проектах.

> 🚧 **Статус:** проект в стадии проектирования архитектуры, код ещё не написан. Этот README описывает целевое видение и будет обновляться по мере реализации.

## Как это работает

Ключевая проблема: у барбершопа, магазина очков и мебельного дизайнера — совершенно разные бизнес-процессы (запись на время / заказ товара / заявка на консультацию). Жёсткая схема БД под "один тип сущности" здесь не работает, поэтому ядро построено на гибкой доменной модели:

```
Сайт-клиент (барбершоп) ──┐
Telegram-бот              ├──► OmniaCRM API ──► PostgreSQL
Сайт-клиент (магазин)     ┘         │
                                     └──► Webhook обратно клиенту (уведомления)
```

| Сущность | Что это | Пример |
|---|---|---|
| `Contact` | клиент бизнеса | имя, телефон, telegram_id, источник |
| `Entity` | универсальная "сделка" с типом и гибкими полями (JSONB) | `booking`, `order`, `inquiry` |
| `Event` | журнал изменений сущности | статус сменился, оплата прошла |
| `Integration` | сайт/бот-клиент со своим API-ключом | сайт барбершопа, Telegram-бот магазина |

Каждый сайт или бот — это просто ещё один `Integration`, который стучится в ядро через REST API и получает вебхуки обратно.

## Возможности

- [ ] **Единый REST API** для регистрации пользователей, заказов, заявок — общий для всех проектов
- [ ] **Интеграция с Telegram Bot API** — приём заказов/записей прямо из бота, синхронно с сайтом
- [ ] **Мультитенантность** — один инстанс ядра обслуживает несколько независимых сайтов-клиентов с изоляцией данных
- [ ] **Гибкая доменная модель** (JSONB/EAV) — одна и та же CRM одинаково обслуживает запись на услугу, e-commerce заказ и лид-заявку без изменения схемы
- [ ] **Webhook-слой** — ядро уведомляет сайты-клиенты о событиях (новый статус, оплата и т.д.)
- [ ] **JWT + API-ключи** — авторизация пользователей и сайтов-клиентов раздельно

## Технологический стек

**Backend**
- [Kotlin](https://kotlinlang.org) 2.3.x
- Java 21 LTS (с прицелом на Java 25 LTS)
- [Spring Boot](https://spring.io/projects/spring-boot) 4.x (Spring Framework 7) + Spring Security
- [PostgreSQL](https://www.postgresql.org) 18 (JSONB под гибкие поля сущностей)
- Flyway — миграции БД
- Gradle (Kotlin DSL)
- Docker / Docker Compose

**Интеграции**
- Telegram Bot API
- REST API + Webhooks для сторонних сайтов
- RabbitMQ — очередь событий *(опционально, на будущее)*

**Мобильное приложение** *(в перспективе)*
- Kotlin Multiplatform + Compose Multiplatform — общий код для Android и iOS

## Чем это не является

OmniaCRM — не замена RetailCRM, amoCRM или Bitrix24. Это разные весовые категории:

| | RetailCRM / amoCRM / Bitrix24 | OmniaCRM |
|---|---|---|
| Готовые интеграции | 100+ (маркетплейсы, эквайринг, доставка) | только свои проекты |
| Аудитория | любой бизнес, self-service | мои собственные сайты и боты |
| Цель | коммерческий SaaS | внутренняя платформа + практика |

В Кыргызстане, для контекста, своих CRM-платформ с нуля почти никто не строит — рынок закрывают amoCRM и Bitrix24 через локальных интеграторов. Так что конкурировать тут не с кем — это чисто инженерная задача для себя.

## Быстрый старт

> Пока в разработке — этот раздел появится вместе с первым рабочим MVP.

Планируемый флоу для локального запуска:

```bash
git clone https://github.com/aelavino2/OmniaCRM.git
cd OmniaCRM
docker compose up -d       # поднимет PostgreSQL и зависимости
./gradlew bootRun          # запустит ядро
```
