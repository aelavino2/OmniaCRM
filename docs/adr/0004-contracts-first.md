# ADR-0004: Контракты до кода

**Дата**: 2026-09-23
**Статус**: accepted
**Участники**: команда проекта
**Требования ТЗ**: REQ-8.3, REQ-8.4, REQ-15.9, issue #4

## Контекст

Ядро на Java и сервисы на Kotlin пишутся параллельно (ADR-0001). Сайты бизнеса написаны на любом стеке — PHP, C# (REQ-8.4). Единственное, что всех связывает, — контракты.

## Решение

Контракты пишутся до реализации и хранятся в модуле `contracts`:

- REST — спецификация OpenAPI; по ней подключаются сайты, Telegram-бот, веб-дашборд и мобильное приложение;
- gRPC — файлы `.proto`;
- события брокера — схемы сообщений.

Код клиентов и серверов генерируется из контрактов в каждом модуле. Изменение контракта — отдельный шаг в PR, до изменения кода.

## Рассмотренные альтернативы

### Сначала код, спецификация генерируется из него
- **Плюсы**: быстрее старт.
- **Минусы**: пока ядро не написано, сервисам и сайтам не на что опереться; контракт меняется незаметно вместе с кодом.
- **Почему нет**: ломает параллельную работу двух разработчиков.

## Последствия

### Положительные
- Сервисы и сайты разрабатываются на заглушках, не дожидаясь ядра.
- Для сайта на любом стеке есть готовая спецификация (REQ-8.4).

### Отрицательные
- Проектировать API приходится заранее; изменение требует обновить контракт и перегенерировать код.

### Риски
- **Реализация отстанет от контракта.** Снижается тестами на соответствие контракту в CI.
