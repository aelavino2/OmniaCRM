# ADR-0006: Мобильное приложение на Kotlin параллельно с веб-дашбордом

**Дата**: 2026-09-23
**Статус**: accepted
**Участники**: команда проекта
**Требования ТЗ**: ТР-12.1 — ТР-12.4, ТР-11.7, ОВ-14
**Дополняет**: ADR-0001

## Контекст

Владелец бизнеса работает и с ПК, и с телефона (ТР-12.2), изменения синхронизируются между устройствами (ТР-11.7). Рассматривался вариант обойтись одним адаптивным веб-дашбордом, но команда решила делать и приложение: проект учебный.

## Решение

Веб-дашборд и мобильное приложение разрабатываются параллельно. Приложение — отдельный модуль `mobile-app` на Kotlin; ADR-0001 дополняется этим модулем. Приложение ходит в ядро по тому же REST-контракту, что и веб-дашборд (ТР-12.3, ADR-0004), и своей логики над данными не содержит. Платформы (только Android или ещё iOS через Kotlin Multiplatform) — ОВ-15.

## Рассмотренные альтернативы

### Только адаптивный веб-дашборд
- **Плюсы**: один интерфейс вместо двух.
- **Минусы**: нет push-уведомлений и нативного опыта.
- **Почему нет**: команда хочет опыт мобильной разработки на Kotlin.

## Последствия

### Положительные
- Push-уведомления и нативная работа на телефоне.

### Отрицательные
- Два клиентских интерфейса, которые нужно держать в согласии.
- Нужен ревьюер для Android-кода: `kotlin-reviewer` настроен на серверный Kotlin.

### Риски
- **Бизнес-логика расползётся по клиентам.** Снижается правилом: вся логика в ядре, клиенты только отображают данные и вызывают API.
