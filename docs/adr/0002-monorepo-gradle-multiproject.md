# ADR-0002: Монорепозиторий и многомодульная сборка Gradle

**Дата**: 2026-09-23
**Статус**: accepted
**Участники**: команда проекта
**Требования ТЗ**: REQ-15.2, REQ-15.7

## Контекст

Система состоит из ядра, трёх сервисов (REQ-7.2), мобильного приложения (REQ-12.4) и общих контрактов. Их пишут двое разработчиков на двух языках (ADR-0001). Изменение контракта обычно затрагивает сразу несколько модулей.

## Решение

Один Git-репозиторий и одна многомодульная сборка Gradle (Kotlin DSL):

```
settings.gradle.kts
contracts/      core/      payment/
notification/   telegram-bot/   mobile-app/
```

Версии зависимостей ведутся в одном каталоге `gradle/libs.versions.toml`.

## Рассмотренные альтернативы

### Отдельный репозиторий на каждый сервис
- **Плюсы**: независимые релизы и права доступа.
- **Минусы**: изменение контракта — несколько согласованных PR в разных репозиториях; версии зависимостей расходятся.
- **Почему нет**: для команды из двух человек это только накладные расходы.

## Последствия

### Положительные
- Изменение контракта и всех его потребителей — один PR.
- Одна команда сборки и один CI на всё.

### Отрицательные
- Сборка всего проекта дольше, чем одного сервиса.

### Риски
- **Модули начнут зависеть друг от друга напрямую.** Снижается правилом ADR-0001: общий код только из `contracts`.
