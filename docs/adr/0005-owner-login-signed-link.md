# ADR-0005: Вход владельца по одноразовой подписанной ссылке

**Дата**: 2026-09-23
**Статус**: accepted
**Участники**: команда проекта
**Требования ТЗ**: REQ-11.4, REQ-8.4, OQ-12, issue #8

## Контекст

Владелец входит в CRM из админ-панели своего сайта; отдельного логина в CRM нет (REQ-11.4). Сайты написаны на разных языках (REQ-8.4), поэтому механизм входа должен быть простым для любого стека.

## Решение

1. Владелец нажимает в админ-панели сайта «Открыть CRM».
2. Сервер сайта отправляет в CRM HTTPS-запрос с секретным ключом бизнеса и данными пользователя (идентификатор, имя, роль).
3. CRM возвращает ссылку для входа — одноразовую, живущую около минуты.
4. Браузер переходит по ссылке, CRM открывает сессию этого пользователя в рамках его бизнеса.

Секретный ключ хранится только на сервере сайта и никогда не попадает в браузер.

## Рассмотренные альтернативы

### OAuth 2.0 / OpenID Connect
- **Плюсы**: стандарт, готовые библиотеки.
- **Минусы**: каждый сайт должен стать провайдером идентификации — это тяжело для небольших сайтов на PHP.
- **Почему нет**: избыточно для входа из одной админ-панели.

### Отдельный логин и пароль в CRM
- **Почему нет**: противоречит REQ-11.4.

## Последствия

### Положительные
- Интеграция на стороне сайта — один HTTP-запрос на любом языке.
- Пароли пользователей сайта в CRM не хранятся.

### Отрицательные
- CRM доверяет сайту: если сервер сайта взломан, злоумышленник войдёт в CRM этого бизнеса.

### Риски
- **Утечка секретного ключа бизнеса.** Снижается возможностью отозвать и перевыпустить ключ; ключ действует только в рамках своего тенанта (REQ-5.1).
- **Перехват ссылки.** Снижается коротким сроком жизни, одноразовостью и только HTTPS.
